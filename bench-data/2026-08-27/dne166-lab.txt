conf-sanity test_166 on a DNE filesystem — lab record
=====================================================
2026-08-27. GCP us-central1-a, two c3-standard-8 rocky-linux-9 instances,
lfu-dne-srv (MGS + 4 MDTs + OST) and lfu-dne-cli (client, conf-sanity runner).
Series: 16 patches on 5afbab284e, the round-11 tree. Build 109s, ldiskfs

WHY THIS LAB EXISTS
-------------------
Two previous labs for test_166 could not see this bug:
  - the single-node lab (2026-08-24) has one MDT;
  - the two-node lab (2026-08-25, tests/lab-166/) also has one MDT — it was
    built for the MDS-is-not-a-client bug, a different one.
The failing autotest session is review-dne-subtest-change, which is DNE.


THE MECHANISM, MEASURED
-----------------------
A stock DNE filesystem ships a ROOT default LMV, with no configuration from
the test framework and none from autotest:

    lfs getdirstripe -D /mnt/lustre
    lmv_stripe_count: 1  lmv_stripe_offset: -1  lmv_hash_type: none
    lmv_max_inherit: -1  lmv_max_inherit_rr: 3

`lmv_stripe_offset: -1` is "space balanced", and with max_inherit_rr set, a
plain mkdir directly under the root is allocated ROUND ROBIN. Measured, eight
plain mkdirs under the root on a 4-MDT filesystem:

    probeA1 -> MDT0    probeA5 -> MDT0
    probeA2 -> MDT1    probeA6 -> MDT1
    probeA3 -> MDT2    probeA7 -> MDT2
    probeA4 -> MDT3    probeA8 -> MDT3

Setting that default LMV explicitly changed nothing — it was already there.
So THREE IN FOUR runs of the old test_166 place $tdir off MDT0000, and the
test scans only $(mdsdevname 1) = MDT0000.

That is the whole failure, and it matches the autotest log exactly:
iteration 1 -> MDT0000 (PASS), iteration 2 -> MDT0001 (FAIL, lost 19 paths).

The code path: lustre/llite/namei.c:1735-1760 sets MF_QOS_MKDIR|MF_RR_MKDIR
when ROOT has a space-balanced default LMV, and lmv_locate_tgt_create()
(lustre/lmv/lmv_obd.c:2258+) then allocates by space rather than following the
parent. Note `fid_is_root()` in lmv_op_default_rr_mkdir() — being directly
under the root is itself a round-robin trigger.

And the fix does override it. `lfs mkdir -i 0 -c 1`, which is what
mkdir_on_mdt0 expands to, is policy step 1 in that same function — "is lfs
mkdir -i N? mkdir on MDT N" — checked before the default LMV:

    probeC1 -> MDT0   probeC2 -> MDT0   probeC3 -> MDT0   probeC4 -> MDT0


ARM 1 — CONTROL, the pre-fix test (plain `mkdir -p`)
----------------------------------------------------
conf-sanity ONLY=166 ONLY_REPEAT=4, MDSCOUNT=4, FSTYPE=ldiskfs.
ONLY_REPEAT is the same mechanism review-dne-subtest-change uses.

  == conf-sanity test 166 ==================================== 13:35:05
  client sees 21 names over 20 objects
  --fid2path resolved 20 objects from 21 names, hardlink once
  PASS 166 (34s)

  == conf-sanity test 166 (repeat 2/4 iter, 0/30 min) ======== 13:35:39
  client sees 21 names over 20 objects
   conf-sanity test_166: @@@@@@ FAIL: --fid2path lost 19 paths
  FAIL 166 (2s)

  tally: PASS 1  FAIL 1

REPRODUCED, and reproduced exactly: pass on the first iteration, fail on the
second, with autotest's message verbatim — "--fid2path lost 19 paths", the
same 19, the same shape. test-framework stops repeating after a failure, which
is why 2 of 4 iterations ran; autotest's session shows the same two.

This is the control the fix has to beat, and it is the honest one: the only
thing changed between the arms is that single line.


ARM 2 — THE FIX (mkdir_on_mdt0)
-------------------------------
Identical configuration; the single line is the only difference.

  == conf-sanity test 166 ==================================== 13:39:02
  --fid2path resolved 20 objects from 21 names, hardlink once   PASS 166 (35s)
  == repeat 2/4 ==  --fid2path resolved 20 objects ...          PASS 166 (2s)

Iterations 2, 3 and 4 are precisely the ones that would have been placed on
MDT0001, MDT0002 and MDT0003 by the round-robin allocator, and are precisely
where the pre-fix arm died. All four resolve all 20 objects.

VERDICT: the failing autotest session is reproduced and the fix closes it.


A LAB TRAP THAT COST A RUN, AND ONE CAVEAT IT EXPOSED
-----------------------------------------------------
`PDSH="ssh -o StrictHostKeyChecking=no -x"`, inherited from tests/lab-166/,
CANNOT serve `do_nodes`: test-framework passes a comma-separated node list, so
`ssh` gets `lfu-dne-cli,lfu-dne-srv` as one hostname and answers

    hostname contains invalid characters

The message is not in the Lustre tree, which is why grepping for it found
nothing. It appears immediately after `Using TIMEOUT=`, at the
`do_nodes $(comma_list $(nodes_list))` line in test-framework.sh:6334.
`llmount.sh` hits it too and exits non-zero *after* mounting everything.

Fix: install `pdsh` + `pdsh-rcmd-ssh` and use `PDSH="pdsh -S -R ssh -w"`.

The caveat it exposed: because that error aborts `setup_noconfig`, and because
test_166 only calls it under `is_mounted $MOUNT ||`, both ARMS above very
likely ran against a filesystem left mounted by the probe rather than one the
test brought up. That does NOT weaken the result -- the arms were identical to
each other, the only difference between them was the one line under test, and
the round-robin placement was measured directly and independently. But it does
mean the arms exercised the is_mounted-true branch, and the setup_noconfig
branch is covered by the 165+166 sequence run below rather than by them.


NEIGHBOUR CHECK — 165 AND 166 IN SEQUENCE, ON DNE, WITH pdsh
------------------------------------------------------------
ONLY="165 166", MDSCOUNT=4, FSTYPE=ldiskfs, PDSH="pdsh -S -R ssh -w".

    PASS 165 (115s)
    PASS 166 (3s)
    PASS=2  FAIL=0  SKIP=0

test_165 brings the filesystem up with setup_noconfig and leaves it up; 166
then takes the `is_mounted $MOUNT ||` branch. That is the ordering that
previously produced a stack_trap/lustre_rmmod race -- green standalone, red in
sequence -- and it is clean here. This run also covers the setup_noconfig path
that the two arms did not.

An earlier attempt at this same check reported `test_165 returned 255` and
FAIL 165 (94s). That was the PDSH trap above and nothing else: with pdsh
installed the identical command passes.
