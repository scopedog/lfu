=== What the run settled

  test0  99 records, 97 with a FID, 48 with a name, last index 185
         The two without a FID are the rename pair, whose cr_tfid is zero.
  test1  99 events collapse to 45 objects -- coalescing is real, and the
         30-write burst on one file is one record
  test2  0 resolved when unasked, 69 of 99 when asked -- the demand mask
         suppresses the lookup, which is what it is for
  test3  -ESHUTDOWN came back unchanged after one record
  test4  seven bad calls refused with -EINVAL

=== Three bugs the lab found that reading did not

1. UPSTREAM, not ours.  lfs changelog --user fails -ENOENT for a user
   registered plainly:

     mdd_device.c:1789-1791  registration writes CHANGELOG_USER_REC unless
                             --mask or --user NAME is given, which write REC2
     mdd_changelog.c:45      the lookup callback matches only REC2
     mdd_device.c:248, :333  every other MDD walker accepts both

   Proven: cl5 (plain) fails, cl6 (registered with -m) works.  This breaks
   the shipped lfs changelog --user, not only llapi_changelog_start_user().

2. Not a bug at all: an earlier run read an empty changelog because the lab
   script's own trap deregistered the user, and deregistering the last user
   purges the log.  The raw llapi_changelog_recv() loop read zero too, which
   is what separated the library from our code.

3. -Wformat-truncation in the test program, caught by the lab's build flags
   and not by the local ones.

=== Two bugs review found before the run

  Coalescing aged on the reader's wall clock rather than the stream's, so a
  catch-up would have flushed every object at once and delivered a record per
  event -- object mode silently degrading to event mode.

  Symlinks did not resolve: O_NOFOLLOW returns ELOOP.  Retried with O_PATH,
  and a symlink's size is left absent rather than reporting the MDT's number
  as a strict one.
