(3) lustre/utils/liblustreapi_pfind.c (line 5070)
    (minor) The two sides of this test come from different hosts: lfsr_event_time is the MDS's cr_time (scan_cl_absorb() stores cr_time >> 30), and fso_looked is time(NULL) on the client.

    If the MDS clock is behind the client's by a second or more, can a change made after the lookup be dropped here?

        lookup of X at client time T      -> rejected, fso_looked = T
        X changes, MDS stamps it T - 1    -> record read later in this run
        T - 1 < fso_looked                -> return 0, X is not looked up again

    That is the case the comment on struct find_since_obj says is kept ("a change made after its lookup, read later in the same run, may make it match"). The window cut compares the same two clocks, but there a skew only moves the edge of the window the user named; here it decides whether a live change is examined at all.

    Would comparing against a time taken from the stream itself (the newest event time read from this MDT when the lookup started) keep both sides on one clock?
