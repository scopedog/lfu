### 1. `lustre/utils/libscan_ldiskfs.c` (line 580)

(minor) If the patch is refreshed: can this arm, or the IS_GARBAGE one below it, ever be taken? The worker handles are opened with SCAN_EXT2_FLAGS, which includes EXT2_FLAG_IGNORE_CSUM_ERRORS. With that flag, ext2fs_get_next_inode_full() never calls ext2fs_inode_csum_verify(), so EXT2_ET_INODE_CSUM_INVALID is never returned:

    if (!(iblock_status[iblk] & IBLOCK_STATUS_CSUMS_OK) &&
        !(scan->fs->flags & EXT2_FLAG_IGNORE_CSUM_ERRORS) && ...)
            retval = EXT2_ET_INODE_CSUM_INVALID;

EXT2_ET_INODE_IS_GARBAGE needs IBLOCK_STATUS_INSANE. Only check_inode_block_sanity() sets that, and it returns early unless EXT2_SF_WARN_GARBAGE_INODES is set, which ext2fs_inode_scan_flags() never sets here.

The comment at the top of the file reads the other way round: it says IGNORE_CSUM_ERRORS makes torn reads "counted and skipped". On a target formatted with metadata_csum, an inode torn mid-update fails its checksum, but it is not detected and is delivered if scan_inode_plausible() passes. ldiskfs targets default to uninit_bg, so this only affects metadata_csum targets.

One option is to keep the flag for ext2fs_open(), which has to get past a live superblock, and then clear it on the per-worker handle (wk->sw_fs->flags &= ~EXT2_FLAG_IGNORE_CSUM_ERRORS). Per-inode checksum failures would then reach this skip arm. The other is to drop the two unreachable cases and correct the comment.
