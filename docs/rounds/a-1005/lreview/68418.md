## Findings

### 1. `Documentation/man1/lfs-find.1` (lines 819–828)

(minor) This paragraph says the log has been coalesced to one record per object, but the paragraph just above says an object touched in two bursts is delivered twice. The second one matches the code: llapi_find_since() sets LLAPI_SCAN_CL_F_COALESCE without LLAPI_SCAN_CL_F_ONCE under --changelog, so coalescing only merges events within sc_min_age.

That means the hardlink example only holds when the create and the link fall in the same burst. If f is created and g is linked later, CL_CREATE "f" and CL_HARDLINK "g" arrive as two records, so -name f matches too (via the first record).

If the patch is refreshed, consider saying the name is the latest one within a burst, and that each separate burst is matched against its own name.

### 2. `Documentation/man1/lfs-find.1` (line 760)

(style) This isn't a bug, but the OPTIONS list is otherwise alphabetical (--atime, --attrs, --blocks, --btime, --ctime, --component-*, ...). --changelog would go before --component-count, and --resolve between --projid and --since, rather than both following --since.

### 3. `Documentation/man3/llapi_find_since.3` (line 39)

(minor) The page never says what value fp_changelog_mdt takes. The code accepts "all" or an exact "<fsname>-MDTnnnn" name (compared against "%s-MDT%04x"), and anything else gets -ENODEV, but the -ENODEV entry below still lists only "no MDT visible / not a Lustre mount".

A few other passages here still describe the anchored form only:
- "Every MDT of the filesystem is read in turn" (What it needs) is not true when fp_changelog_mdt names one MDT.
- LLAPI_SINCE_INDEX is "refused ... on a filesystem with more than one", but naming a single MDT in fp_changelog_mdt lifts that, which is what the code and lfs-find(1) say.

The kernel-doc above llapi_find_since() opens with "Candidates come from every MDT's changelog" too. If the patch is refreshed, these are worth a sentence each.
