## Findings

### 1. `/COMMIT_MSG` (line 7)

(style) The summary has no verb. Something like "lfs: add find --since to search the changelog" would read as an imperative and still name the option.

### 2. `/COMMIT_MSG` (line 80)

(minor) This paragraph reads as a changelog of an earlier patchset. "answered -ENODEV" and "the search printed nothing and exited 0" are in the past tense, and they describe behaviour of a llapi_find_since() that master never had.

Could it just say what the code does: the mount is looked up from realpath(path) so that the subtree test and the mount agree for symlinked, relative and $MOUNT2 paths?

### 3. `lustre/utils/liblustreapi_pfind.c` (line 4841)

(minor) The return value is dropped here. find_rec_to_lmv() returns -ENOMEM when the realloc for a large foreign LMV fails, and by that point it has already zeroed the header of fp_lmv_md.

find_decide() then runs --mdt-count, --hash-type and --foreign against lum_magic == 0 and lum_stripe_count == 0, which gives a wrong answer with no error. find_device_cb() checks the same call and returns rc. Should this do the same, or count the object as undecided?

### 4. `lustre/utils/liblustreapi_pfind.c` (line 4937)

(minor) On a fileset (subdirectory) mount this counts more than unlinked objects. mdt_path_current() returns -ENOENT for any FID that is not under the export's root, so every changelog record outside the fileset ends up here.

The end-of-run warning would then say e.g. "900 of 920 changed objects no longer exist" when they exist but are not visible through this mount. The answer itself is still correct, but the diagnostic misleads. Could the wording cover both cases, or could the outside-the-fileset case be counted separately?

### 5. `lustre/utils/liblustreapi_pfind.c` (line 5191)

(style) "dropped with it" points at an errno that has not been printed yet. lfs prints "failed for '...'" only after this warning, and a library caller may never print it at all.

Would something like "%llu objects could not be checked: rc = %d" with fss_scan_rc be clearer on its own?
