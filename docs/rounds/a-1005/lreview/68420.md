### 2. `lustre/tests/sanity.sh` (line 22759)

(suggestion) The 15s gap only protects the old side of the window. new1/new2 stay inside "--since 8s" only if the sync after them, the 2s sleep and the plain find all fit in 8s, which leaves about 6s for sync plus the find:

    new created at t1; --since find runs at t1 + sync + 2 + find
    new kept only if sync + find <= 6s

The old files are excluded by at least 9s whatever sync does. So a slow sync after the touch, which is the case the comment above describes, is the one that breaks the test. The test also depends on how far the MDS clock (rec->lfsr_event_time) and the client's time() disagree.

If the test is refreshed, one fix is to take the anchor in the middle of the gap and use --since @$mid, e.g. sleep 7; mid=$(date +%s); sleep 8. That gives roughly equal margin on both sides, and it no longer depends on how long the sync after new1/new2 takes.
