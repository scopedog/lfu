## Findings

### 1. `lustre/utils/liblustreapi_pfind.c` (line 3708)

(minor) Should the refusals be checked before this early return? Returning 1 for a non-matching --mdt skips the --ost-over-an-MDT refusal below. It also skips the OST check for the layout options in llapi_find_device(), which only runs after find_device_targets() has returned 0. The --ost early return at the matched == !!param->fp_exclude_obd check has the same problem.

So a search that can never be answered gets a different result on each device of a sweep:

    --mdt MDT0001 --ost OST0000  over MDT0000  -> 0, empty
    --mdt MDT0001 --ost OST0000  over MDT0001  -> -ENOTSUP
    --ost OST0005 --stripe-count 2 over OST0000 -> 0, empty
    --ost OST0005 --stripe-count 2 over OST0005 -> -ENOTSUP

The commit message says these combinations are refused. Running all the kind checks (--mdt over an OST, --ost over an MDT, layout options over an OST) before either early return would refuse them on every device.
