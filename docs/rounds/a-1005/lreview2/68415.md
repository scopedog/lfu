### 2. `lustre/utils/liblustreapi_scan_changelog.c` (line 612)

(minor) sl_accepted is assigned rather than only ever raised, so under _COALESCE it can move backwards. The busy-limit path in scan_cl_object_one() delivers an object under the current record's index. Any object still in the cache has a lower co_index, and when it is flushed afterwards sl_accepted drops back to that lower index.

Example with _COALESCE|_CLEAR: B is touched at index 100. A hits the hold limit at 101 and is delivered (sl_accepted = 101). Then the log ends and flush(all) delivers B (sl_accepted = 100). The final scan_cl_clear() stops at 100, so record 101 stays in the log even though A was delivered from it. The next run delivers A again, and _ONCE cannot help because its set is per run. A CL_MARK delivered while objects are held has the same effect.

scan_cl_held_first() already keeps the clear behind every held object, so keeping only the highest index looks safe:

    if (o->co_index > sl->sl_accepted)
            sl->sl_accepted = o->co_index;

The same applies to the filter and _ONCE assignments above. It also stops `upto - sl->sl_clear_walked` in scan_cl_clear() from wrapping when upto falls below the last walk.
