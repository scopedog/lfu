## Findings

### 1. `lustre/utils/liblustreapi_pfind.c` (line 4792)

(minor) For a library caller, can this fire on a find_param that never asked for a depth? llapi_find_param_alloc() is a plain calloc(), so fp_max_depth is 0 unless the caller knows to set it to (unsigned int)-1. The call then fails with -ENOTSUP and "--maxdepth and --mindepth describe a walk", naming options the caller never used.

find_device_supported() treats 0 as unset for this reason ("0 too: llapi_find_param_alloc() zeroes it"). The llapi_find_since.3 examples set fp_max_depth = -1, but the page never says it is required. Accepting 0 here the way the device path does, or documenting the requirement in llapi_find_since.3, would keep the two entry points consistent.

### 2. `lustre/utils/liblustreapi_pfind.c` (line 5481)

(minor) What does --changelog report on a fileset mount (or a nodemap fileset)? The changelog covers the whole filesystem, while fid2path and llapi_scan_fid() resolve nothing outside the fileset. So an object outside it looks exactly like one unlinked since its event.

- Without --resolve, llapi_scan_rec_path() answers -ENOENT and find_decide() prints the FID.
- With --resolve, llapi_scan_fid() answers -ENOENT, the object is counted as gone, and with the root at the mount it goes on to find_changelog_rec_cb() and prints by FID.

In both cases `lfs find /mnt/fileset --changelog all` lists every changed object in the filesystem. The ones outside the fileset show up as FIDs and are counted in "objects have no pathname and are named by FID". st.fss_fileset is still computed, but its only reader is the gone warning, which is now skipped under --changelog. So a caller isn't told that some of those FIDs are outside the fileset rather than deleted. Should the fileset case at least be reflected in the warning, or be refused the way a subtree is?

### 3. `lustre/utils/liblustreapi_pfind.c` (line 5522)

(style) This isn't a bug, but the re-flow left two short lines in this kernel-doc block: "names.  What happens next depends on" / "the source.", and "-ENODEV for a --changelog MDT name" / "that names no MDT ...". Worth re-filling if the patch is refreshed.

### 4. `Documentation/man3/llapi_find_since.3` (line 172)

(minor) ERRORS now has two separate -ENOTSUP entries, this one and the fp_thread_count one above -ENODEV. Merging them into one entry would make the list easier to scan. Also, since this is the library page, the refused predicates could be named by their find_param fields (fp_mdt_uuid, fp_obd_uuid, fp_format_printf_str, ...) rather than only by their lfs find spellings. A caller of llapi_find_since() never types --mdt or -printf.
