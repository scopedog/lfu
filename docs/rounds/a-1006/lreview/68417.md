## Findings

### 1. `lustre/utils/liblustreapi_pfind.c` (line 5011)

(suggestion) Every candidate gets the full gather before the subtree test runs. fss_want always has at least LLAPI_SCAN_FID | LLAPI_SCAN_MODE, which are in LLAPI_SCAN_MDT_MASK, so llapi_scan_fid() does common_param_init() (~70KB of callocs), an openat() of the parent and the getattr ioctl for each changed object in the whole filesystem. Only then does find_since_rec_cb() -> find_since_pick() reject the ones outside the root.

For `lfs find /mnt/lustre/small_dir --since 1d` on a busy filesystem, nearly all of that work is thrown away. llapi_scan_fid()'s kernel-doc names this case, a subtree filter over a changelog's FIDs, as the reason lfsp_filter runs before the open.

Could the subtree test (and the name-independent part of find_prefilter(), such as -type) move into sp.lfsp_filter? The filter has no nlink yet, but walking the other links with llapi_fid2path_at() there is one ioctl for a file with a single link (linkno does not advance), which is still much cheaper than the gather.

### 2. `lustre/utils/liblustreapi_pfind.c` (line 5252)

(suggestion) With a time anchor every MDT's log is read from its first surviving record. If another registered user (a policy engine, or `lfs changelog_clear`) has already cleared past the anchor, the objects changed between the anchor and the first surviving record are missing from the answer. The run still exits 0 with no warning.

On sites that run changelog consumers this is the normal state, so `--since 1d` can return much less than a day's changes. That is the same "short answer with nothing to say so" this patch refuses for a bare index on multi-MDT filesystems. Could the oldest record seen on each MDT be compared with fss_since, so the run warns when the log does not reach back to the anchor?

### 3. `lustre/utils/liblustreapi_pfind.c` (line 5277)

(minor) Nothing has printed "it" by the time this warning appears. fss_scan_rc is only returned, and lfs_find() prints its "failed for ..." line after llapi_find_since() returns. For a library caller, nothing prints the errno at all. If the patch is refreshed, consider naming the error here, e.g. "%llu objects were dropped after errors, the first: %s" with strerror(-st.fss_scan_rc).
