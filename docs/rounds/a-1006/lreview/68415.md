## Findings

### 1. `lustre/utils/liblustreapi_scan_changelog.c` (line 1062)

(minor) A failed clear is logged and then forgotten here, so llapi_scan_changelog() still returns 0 to a caller that asked for LLAPI_SCAN_CL_F_CLEAR.

One way to hit it is an sc_user that is not registered (a typo, or a user that was deregistered). Without sc_type_mask the plain llapi_changelog_start() reader never checks the user, so the whole scan runs and delivers. Each clear then fails:

    scan_cl_clear() -> llapi_changelog_clear() -> write("clear:cl7:N")
        -> mdd_changelog_clear(): "no entry for user" -> -ENOENT

The caller only sees rc == 0. A consumer that relies on _CLEAR to keep the MDT's log bounded has no signal that nothing was purged, and the backlog keeps growing. That is the failure the NOTES section warns about.

Could the first clear failure be kept, for example in an sl_clear_rc, and returned when the scan otherwise ends with 0? A consumer's own stop value would still win. llapi_scan_changelog.3 ERRORS could then list it.
