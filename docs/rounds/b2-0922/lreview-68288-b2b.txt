(1) lustre/utils/liblustreapi_scan_device.c (line 1850)
    (defect) Can this ever be true? SCAN_BACKEND_MAX is 2, so kind is always one of SCAN_BACKEND_LDISKFS or SCAN_BACKEND_ZFS and *pp_live is a constant false.

    That propagates to fds_tgt_live -> fc_tgt_live, so find_lookup_spares_tgt() collapses to the LLAPI_SCAN_OWNER test and the llapi_fid2path_at() arm in find_decide() is only ever reached for OST objects. On an MDT --fid2path never falls back to a lookup, even when the MDT is mounted and the mount could answer -- which is exactly the configuration test_301 sets up (an ldiskfs MDT scanned in service).

    The user-visible effect is on DNE: an object whose ancestors are on another MDT is not in this target's map, so it is counted as having no pathname rather than looked up through MOUNT, which is what lfs-find.1 and the comment above find_decide()'s lookup arm both promise.

    If the intent is that a raw-device scan never trusts the target, it would be clearer to drop fc_tgt_live and say so in the man page; if the in-service case is meant to work, the test needs to be about the target's state rather than about which backend is reading it.

(2) Documentation/man1/lfs-find.1 (line 909)
    (minor) This paragraph documents a fallback that the code cannot take today -- see the note on liblustreapi_scan_device.c. fc_tgt_live is always false, so on an MDT no lookup is made whether or not it is in service, and a DNE object the map cannot place is always counted as nameless.

    It also reads against the commit message, which lists "on DNE an object whose parents are on another MDT" among the objects that are counted and reported rather than printed.

(3) Documentation/man1/lfs-find.1 (line 1075)
    (minor) If the patch is refreshed, --fid2path and --paths could use an EXAMPLES entry each. --device from earlier in the series got one just above, and these two are the headline way a user turns a scan's FIDs into names -- something like

        # lfs find --device /dev/vdb --fid2path /mnt/testfs --type f
        # lfs find --device /dev/vdb --paths --type f
