## Findings

### 1. `lustre/utils/lustreapi_scan_backend.h` (line 146)

(minor) The plugin keeps its symbol name, scan_ldiskfs_open, but its signature changes from 3 arguments to 4. The comment in scan_backend_load() says an out-of-step scan_*.so is "a real arrival", and osd-ldiskfs-mount has no versioned Requires on the library, so a pair from different builds can happen. The dlsym() check does not catch this one, because the symbol is still there.

With a scan_osd_ldiskfs.so built from 68156 and this liblustreapi:

    sb_open(device, search, &handle, tgt)
    -> old scan_ldiskfs_open(device, tgtp = search, tgt = &handle)
       memset(&handle, 0, sizeof(struct llapi_scan_tgt));  /* 80 bytes over an 8-byte local */
       *tgtp = t;                                          /* search is NULL from lfs: SIGSEGV */

Nothing has landed yet, so if the series is refreshed, moving the search argument into 68156's sb_open() would keep the plugin ABI the same in every landed commit. Otherwise a new symbol name or an ABI tag would turn this into the clean "is not a device scan backend" refusal.
