## Findings

### 1. `Documentation/man3/llapi_find_since.3` (line 149)

(minor) If the patch is refreshed: the example declares struct find_param on the stack, but llapi_find_param_alloc(3) asks applications not to do that so the allocation matches the running library's struct. This patch adds three fields to that struct, so this is the case the advice is about.

Could the example use llapi_find_param_alloc() and llapi_find_param_free(), and show #include <lustre/lustreapi.h> as the other llapi pages do?

### 2. `Documentation/man3/llapi_find_since.3` (line 56)

(minor) This section lists a registered changelog user and CAP_DAC_READ_SEARCH, but it doesn't say that the changelog device is readable only by root by default. lfs-find.1 in this patch does say it. A caller who isn't root fails in llapi_changelog_start() and gets -EACCES from the first MDT, before any FID is resolved, so that is the requirement a library user runs into first. Could one sentence about it go here, next to the fid2path one?
