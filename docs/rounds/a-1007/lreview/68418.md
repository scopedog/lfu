### 3. `lustre/utils/liblustreapi_pfind.c` (line 3700)

(minor) Under --changelog the FID is always available, and the commit message promises "a pathname where the FID still resolves to one and the FID where it does not". When llapi_scan_rec_path() fails with anything other than -ENOENT/-ENODATA/-EINVAL, though, the match isn't printed at all. That covers a path longer than pbuf, or -EIO/-ETIMEDOUT while an MDT fails over.

Only the first such failure is logged, so every later match that fails the same way disappears without a message. The exit status does now report the failure, but the output no longer says which objects matched. Should this arm also print the FID when fc_fid_when_lost is set, the same way the -ENOENT arm above does?
