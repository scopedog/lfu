### 1. `lustre/utils/liblustreapi_pfind.c` (line 5627)

(minor) Is "Nothing was lost" true when the third read finds oldest > anchor + 1?

Reaching this branch means the anchor record was present (or anchor + 1 was the oldest) at the first read, and nothing at or after the anchor existed at the second. If records anchor+1..K are written and then cleared by another changelog user between the second and third reads, oldest comes back as K+1. `oldest >= anchor` then continues, and the run resumes at anchor + 1 with anchor+1..K gone. That is the same purge the first check refuses as -ESTALE a few lines up.

The window is narrow, but this function has the number it needs. Something like this would close it:

    if (oldest == 0 || oldest == anchor + 1)
            continue;
    if (oldest > anchor + 1)
            /* purged past the anchor, as above */

It would leave the restart refusal for oldest <= anchor.
