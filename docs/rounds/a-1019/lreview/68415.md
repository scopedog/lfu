## Findings

### 1. `lustre/utils/liblustreapi_scan_changelog.c` (line 1284)

(minor) If lfsc_type_mask and the user's registered mask don't overlap, the caller gets every record type, not none. mdc_changelog.c sets

    crs->crs_user_mask = in.cf_mask & out.cf_mask;

and chlg_read_cat_process_cb() filters only `if (crs->crs_user_mask && ...)`. So an intersection of 0 means no filtering at all. For example, cl1 registered with `-m CREAT` and lfsc_type_mask = BIT(CL_UNLINK) delivers CREAT, CLOSE, MARK and so on to a consumer that asked only for unlinks.

The man page warns about this, but the library has the mask and the record type in hand. If the patch is refreshed, could the read loop also drop records whose type isn't in the mask, before ss_seen?

    if (scl.lfsc_type_mask != 0 &&
        !(scl.lfsc_type_mask & (1ULL << rec->cr_type))) {
            llapi_changelog_free(&rec);
            continue;
    }

That makes the empty-intersection case return what was asked for, and the 'Keep the mask within the user's own' caveat in llapi_scan_changelog.3 can go.
