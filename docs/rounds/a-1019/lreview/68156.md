## Findings

### 1. `lustre/utils/liblustreapi_scan_device.c` (line 768)

(minor) On an OST that never got OBD_ROCOMPAT_IDX_IN_IDIF (formatted before 2.6, with od_index_in_idif still 0), osd_create() stores the IDIF in the LMA with OST index 0:

    fid_to_ostid(fid, oi);
    ostid_to_fid(tfid, oi, 0);

osd_check_lma() treats such an LMA as old and rebuilds it with the real index before comparing. Here the raw lma_self_fid goes into lfsr_fid with LLAPI_SCAN_FID set. So on OST0003 an object comes back as [0x100000000+...:oid:0] instead of [0x100030000+...:oid:0], and two OSTs with the same oid give the same FID.

The label already gives tt_index. When fid_is_idif() && fid_idif_ost_idx() == 0 on an OST with LLAPI_SCAN_TGT_INDEX, should this rebuild the FID with ostid_to_fid(..., tt_index) the way the OSD does? If not, it may be worth a line in llapi_scan_device.3.

### 2. `Documentation/man3/llapi_scan_device.3` (line 465)

(minor) -EIO is documented only as a failed read of the inode table, but scan_errcode() also returns it for every ext2fs_open() error it does not map: a truncated image (EXT2_ET_SHORT_READ), a corrupt superblock or bad group descriptors. It is also returned when ext2fs_read_inode_bitmap() fails in scan_ldiskfs_worker_init(), and for ext2fs_open_inode_scan() or ext2fs_inode_scan_goto_blockgroup() failures. -ENOMEM (calloc() of the workers, the backend's allocations) is not listed at all. If the page is refreshed, consider widening the -EIO entry and adding -ENOMEM.

### 3. `include/uapi/linux/lustre/lustre_fid.h` (line 372)

(style) This isn't a bug, but now that fid_is_root() lives in the UAPI header, everything around it (lu_fid_eq(), fid_is_igif(), fid_is_sane(), fid_seq_is_root(), ...) returns bool. If the patch is refreshed, consider making this one bool as well.
