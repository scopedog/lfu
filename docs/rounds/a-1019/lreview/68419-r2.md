## Findings

### 1. `lustre/utils/liblustreapi_pfind.c` (line 5516)

(minor) Is this probe enough when the cookie sits in a sticky directory such as /tmp? Creating and unlinking our own temporary succeeds there. The later rename(tmp, cookie) in find_cookie_write() needs more: it fails with EPERM when the existing cookie belongs to another uid and the directory belongs to someone else too.

For example, root seeds /tmp/job.ck once (0644), then a cron job as another user runs the following sequence:

    find_cookie_read()   -> open O_RDONLY ok
    find_cookie_check()  -> probe create/unlink ok
    ... every match printed ...
    find_cookie_write()  -> rename() = -EPERM

That gives "cannot rewrite" on every run, and each run repeats the last one. The pre-pass exists to stop exactly this case, much like the root-owned 0755 directory case the comment above describes. A check along the lines of (dir has S_ISVTX && cookie st_uid != geteuid() && dir st_uid != geteuid()) would catch it before anything is printed.
