## Findings

### 1. `lustre/utils/lfs.c` (line 6604)

(minor) If the patch is refreshed: this is a second copy of find_asks_layout() from liblustreapi_pfind.c, and the two lists have to stay identical. skip_ost depends on it.

Say a layout predicate is later added to the library's list but not to this one. Then `lfs find --local --that-option` on a node serving an MDT and an OST would no longer skip the OST. llapi_find_device() would refuse it with ENOTSUP, and the sweep would exit non-zero even though the MDT answered in full.

Could the library export the one list instead, e.g. as an llapi_* helper, or through lustreapi_internal.h, which lfs.c already includes?
