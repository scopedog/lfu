## Findings

### 1. `Documentation/man1/lfs-find.1` (line 1003)

(minor) This sentence pins the encrypted-directory limit on --paths alone, but --fid2path on an MDT goes through the same map and stops at the same place:

    find_decide() -> scan_dirmap_path() -> e->sd_encrypted -> -ENOENT

There is no fallback lookup through MOUNT (fc_dirmap != NULL), so an object below an encrypted directory gets counted as nameless even when MOUNT holds the key. If the page is refreshed, "On an MDT, neither option names an object below an encrypted directory" would cover both. The NOTES list in llapi_find_device.3 (".lustre, and under DNE anything whose ancestors live on another MDT") could mention it as well.

### 2. `lustre/utils/lfs.c` (line 6646)

(minor) This isn't a bug, but -printf together with --paths or --fid2path is refused only by find_device_supported() in the library. So a sweep gets the refusal once per target instead of once:

    lfs find --local --paths -printf '%p\n'

On a server with several MDTs this prints the library error plus "failed for '<dev>'" for each one. The function already refuses --maxdepth and --xattr here ("Refused once here, not once per target of a sweep"). If the patch is refreshed, the -printf check could sit beside this --paths/--fid2path one.
