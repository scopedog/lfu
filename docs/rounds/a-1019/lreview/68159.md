## Findings

### 1. `lustre/utils/liblustreapi_pfind.c` (line 4534)

(suggestion) The undecided count only reaches the caller as this message. llapi_find_device() returns 0 either way, and struct llapi_scan_stats has no field for it. ss_skipped covers unreadable objects, and ss_emitted counts every delivered record, shards included.

So a program can't tell a complete answer from one where, for example, most striped files had no trusted.som and were left out of a -size search, unless it scrapes stderr. Since lfsp_stats is documented as the way a program sees a partial answer, could this count be returned there too, or through a find_param field?

### 2. `Documentation/man3/llapi_find_device.3` (line 262)

(minor) "every regular file over a gigabyte" promises more than this search returns. On an MDT a striped file's size is only known from trusted.som (or the inode, for Data-on-MDT). Any file without that is counted undecided and isn't printed, which DESCRIPTION says. If the page is refreshed, could the example say it prints the files whose size the MDT records, and point at the undecided warning?
