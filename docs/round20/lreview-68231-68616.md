## 68616 — three findings, two fixed, one recorded

The reviewer reproduced the sweep independently, which is worth as much
as the findings:

> all 378 pages under `Documentation/` were run with the parent and with
> this commit, and `lustreapi.7` is the only page whose output moves (47
> messages to 9, and the 39 perl uninitialized-value warnings go away).

### `(1)` — the count in the message was wrong, and I measured it

The message said "28 warnings". Running the parent script against the
parent page:

    26  SEE ALSO lines must be of the following form
    13  '.PP' should end with ','
     2  SEE ALSO lines must sorted by section number
     1  Prefer referencing to Lustre with the lustre(7) man
    ---
    42  warnings, of which 26 + 13 = 39 are the ones described

So **39**, exactly as the finding says, and its breakdown (13 description
lines + 13 `.PP` malformed, plus 13 comma) matches the measurement line
for line. The message now gives that breakdown and the 42 total, because
the paragraph below it independently says "39 uninitialized-value
warnings" from perl — a **different** 39, and two bare 39s a paragraph
apart would read as one number repeated.

The reviewer also noticed the earlier revision had it right: "Patch set 2
said 39 here; it seems to have been changed while the paragraph below it
was reworded." That is what happened.

### `(2)` — right conclusion, wrong reason

The message said "no page in the tree has a spacing macro before a .SS
today". **Two do**, and I confirmed both:

    Documentation/man3/llapi_changelog_recv.3   .PP -> .SS "Changelog record format"
    Documentation/man8/lnetctl.8:888            .P  -> .SS "Show UDSPs"

The sweep still comes out unchanged, but for the reason the reviewer
gives rather than the one claimed: both headers are **quoted**, so the
intervening `/^\.(S[HS]) \".*\"/` match resets `$1` to the correct SS
before it is read. The input that reaches the bug is a spacing macro
before an **unquoted** `.SS`, and a sweep of the tree finds none.

Reworded to say that, since "there is no such page" and "there is no such
page of the kind that matters" are different claims and only the second
is true.

### `(3)` — recorded, not implemented

A stray comma on the **last** reference of a `.SS` run is not reported,
where the last reference of a flat list is: a `.SS` is handled early and
skips past the SEE ALSO block, so nothing compares against it.
`lustreapi.7` is clean today, so it is latent rather than a live miss.

Not implemented, and the reason is the maintainer's own: adilger
declined the *other* looseness suggestion on this same file with **"This
is not critical, and patch is still an improvement over the previous
code."** Adding a new check to `checkpatch-man.pl` could surface findings
across 378 pages, which is exactly the scope growth that comment is
warning off. Worth its own patch if anyone wants it.
