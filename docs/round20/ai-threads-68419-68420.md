### `6fc1aa25` — the test existed but only proved it did not crash

    $LFS find $m --changelog all -name '*' > /dev/null ||
            error "--changelog -name failed"

That is the segfault case and nothing more: it would pass just as well if
`-name` matched everything.  Added a selective pair at the **end** of
160ab.

**Two wrong attempts first, both caught on the lab, and both worth
recording:**

1. I put the block mid-test and cleared the changelog to make a nameless
   object.  That purged the records a later assertion needed, and 160ab
   failed at `--changelog --resolve -size did not report f1` -- a
   fixture mutated under the test that still uses it.
2. I then avoided clearing by cutting a time window with `--since @<ts>`
   after `f1`'s creation.  **That does not produce a nameless object.**
   `--since` cuts on the *event time* of an object the whole log was
   read to build, and coalescing carries `co_name` forward from
   whichever record had one -- so `f1` still had its name and `-name f1`
   matched it.  The lab said so; the code reading had not.

The version that works clears the log **last**, after everything above it
is done with it, then only writes to `f1`:

    changelog_clear 0
    echo more >> $DIR/$tdir/f1        # data stores: no name
    echo new > $DIR/$tdir/f_new.log   # a creation: named

    -name 'f_new.log' -> must report f_new.log
    -name 'f1'        -> must NOT report f1

The pair is self-controlling: the positive assertion proves the query
works, so `f1`'s absence is the nameless record being counted undecided
rather than an empty answer.  A `-name` that matched everything fails the
second; one that matched nothing fails the first.

### `39df2275` — declined, with a reason

The suggestion is to move `--changelog` up among the `--component-*`
entries and `--resolve` before `--size`.  Alphabetically that is right,
and the page is otherwise roughly name-ordered.

Declined because it would scatter one feature across the page.
`--since`, `--since-cookie`, `--changelog` and `--resolve` are the four
changelog options and they are contiguous today, sitting between `--size`
and `--skip` -- which is *exactly* where `--since` and `--since-cookie`
belong alphabetically, as the comment itself grants.  The other two ride
with them.  `--resolve` in particular means nothing without
`--changelog`: it is refused on its own, so filing it under `r`, twelve
entries away from the only option it works with, costs the reader more
than the ordering buys.  The SYNOPSIS makes the dependency structural --
`[--changelog MDTNAME|all [--resolve]]` -- and splitting that would be
wrong outright.

The page already deviates where meaning warrants: `--ls` before
`--links`, `--mdt-hash` before `--mdt-count`, `--extension-size` after
`--stripe-size`.

    lustre/utils/   contrib/scripts/checkpatch-man.pl

are llite/OSC/OST paths reached by syscall, not through `lfs` or

reach a module, and they do not: the `.m4` adds a compile test for
libzpool headers gating the *userspace* `scan_zfs.so` plugin, and the
spec change packages `scan_zfs.so`/`scan_ldiskfs.so`.  Neither alters
how any kernel module is built.

The lab failures are this rig's own -- fallocate against a 10MB hard
limit on small flakey-dm OSTs -- and I stopped the run once attribution
was settled, since the file-scope argument settles it more firmly than
